## 常见问题

### 侧边栏中出现 Codex 未编辑过的文件

如果你的项目位于 Git 仓库中，审查面板会根据项目的 Git 状态自动显示更改，包括 Codex 未做出的更改。

在审查窗格中，你可以在已暂存的更改和尚未暂存的更改之间切换，也可以将分支与 main 进行比较。

如果你只想查看 Codex 上次轮次的更改，请将 diff 窗格切换到「上次轮次更改」（Last turn changes）视图。

了解更多关于如何使用审查窗格的信息。

### 从侧边栏中移除项目

要从侧边栏中移除项目，请将鼠标悬停在项目名称上，点击三个点并选择「移除」（Remove）。要恢复它，请使用「Threads」旁边的「添加新项目」（Add new project）按钮或使用 `Cmd+O` 重新添加该项目。

### 查找已归档的对话

已归档的对话可以在「设置」（Settings）中找到。当你取消归档某个对话时，它将重新出现在侧边栏的原始位置。

### 侧边栏中只显示部分对话

侧边栏允许根据项目状态筛选对话。如果你缺少某些对话，请点击「Threads」标签旁边的筛选图标，切换到「按时间顺序」（Chronological）。如果仍然看不到该对话，请打开「设置」并检查「已归档的聊天」或「已归档的对话」部分。

### 代码在 worktree 上无法运行

Worktree 创建在不同的目录中，并且只继承已提交到 Git 的文件。根据你管理项目依赖和工具的方式，你可能需要使用本地环境在 worktree 上运行一些设置脚本。或者，你可以在常规的本地项目中检出更改。请查阅 worktree 文档以了解更多信息。

### 应用无法识别队友共享的本地环境

本地环境配置必须位于项目根目录下的 `.codex` 文件夹中。如果你在包含多个项目的 monorepo 中工作，请确保在包含 `.codex` 文件夹的目录中打开项目。

### Codex 请求访问 Apple Music

根据你的任务，Codex 可能需要浏览文件系统。macOS 上的某些目录（包括音乐、下载或桌面）需要用户的额外批准。如果 Codex 需要读取你的主目录，macOS 会提示你批准访问这些文件夹。

### 自动化任务创建了大量 worktree

频繁的自动化任务可能会随时间积累大量 worktree。请归档不再需要的自动化运行记录，并避免固定运行，除非你打算保留其对应的 worktree。

### 选择错误目标后恢复提示词

如果你不小心以错误的目标（本地、Worktree 或云端）启动了一个对话，你可以取消当前运行，并通过在输入框中按上箭头键来恢复之前的提示词。

### 功能在 Codex CLI 中可用但在 Codex 应用中不可用

Codex 应用和 Codex CLI 使用相同的底层 Codex 代理和配置，但可能在任何时候依赖不同版本的代理，并且某些实验性功能可能会先在 Codex CLI 中推出。

要获取系统上 Codex CLI 的版本，请运行：

```bash
codex --version
```

要获取 Codex 应用内置的 Codex 版本，请运行：

```bash
/Applications/Codex.app/Contents/Resources/codex --version
```

## 反馈与日志

在消息输入框中输入 `/` 可以向团队提供反馈。如果你在现有对话中触发反馈，你可以选择将会话与反馈一起分享。提交反馈后，你会收到一个会话 ID，可以将其分享给团队。

要报告问题：

1. 在 Codex GitHub 仓库中查找已有问题。
2. 提交新的 GitHub issue。

更多日志可在以下位置找到：

- 应用日志（macOS）：`~/Library/Logs/com.openai.codex/YYYY/MM/DD`
- 会话记录：`$CODEX_HOME/sessions`（默认：`~/.codex/sessions`）
- 已归档的会话：`$CODEX_HOME/archived_sessions`（默认：`~/.codex/archived_sessions`）

如果你分享日志，请先检查以确保其中不包含敏感信息。

## 卡住状态与恢复模式

如果某个对话似乎卡住了：

1. 检查 Codex 是否正在等待审批。
2. 打开终端并运行一个基本命令，如 `git status`。
3. 使用更小、更聚焦的提示词启动一个新对话。

如果你误取消了 worktree 的创建并丢失了提示词，请在输入框中按上箭头键来恢复它。

## 终端问题

**终端似乎卡住了**

1. 关闭终端面板。
2. 使用 `Cmd+J` 重新打开它。
3. 重新运行一个基本命令，如 `pwd` 或 `git status`。

如果命令的行为与预期不同，请先在终端中验证当前目录和分支。

如果仍然卡住，请等待活跃的 Codex 对话完成，然后重启应用。

**字体渲染不正确**

Codex 在审查窗格、集成终端以及应用内显示的任何其他代码中使用相同的字体。你可以在「设置」面板中将字体配置为「Code font」。
