# 子智能体 (Subagents)

> 在 Codex 中使用子智能体和自定义智能体

Codex 可以运行子智能体工作流，通过并行生成专门的智能体，然后将它们的结果汇总为一次响应。这对于高度并行的复杂任务特别有用，例如代码库探索或实现多步骤功能计划。

通过子智能体工作流，你还可以定义自己的自定义智能体，根据任务配置不同的模型和指令。

## 可用性

当前 Codex 版本默认启用子智能体工作流。

## 典型工作流

### 1. 启动子智能体

在主线程中描述任务，Codex 会自动将并行子任务分配给子智能体：

```
在这个代码库中探索并识别关键组件，同时分析依赖关系。
```

### 2. 子智能体并行工作

每个子智能体在隔离环境中独立工作：
- 读取文件
- 分析代码
- 生成报告

### 3. 结果汇总

子智能体完成后，Codex 将结果汇总到主线程，呈现综合分析和建议。

## 管理子智能体

| 操作 | CLI 命令 / 操作 |
| --- | --- |
| 查看活动子智能体 | `/agents` |
| 切换活动线程 | `/agent` |
| 创建新的工作分支 | `/fork` |

## 审批和沙箱控制

每个子智能体继承主会话的审批和沙箱设置。你可以在子智能体级别控制：

- **审批模式**：子智能体何时需要征求许可才能运行命令
- **沙箱模式**：子智能体可以读取或写入哪些文件

## 自定义智能体

你可以定义自己的自定义智能体，配置不同的：

| 配置项 | 说明 |
| --- | --- |
| **模型** | 为子任务选择不同的模型（如 GPT-5.4、GPT-5.3-Codex） |
| **指令** | 为特定任务提供专用指令 |
| **工具访问** | 控制子智能体可以使用的工具集 |

### 配置示例

```toml
[agents.reviewer]
model = "gpt-5.4"
instructions = "你是一名资深代码审查员。审查代码变更，识别潜在问题。"
```

## 使用子智能体的最佳实践

- ✅ 将边界清晰的工作从主线程卸载给子智能体
- ✅ 保持主智能体专注于核心问题
- ✅ 对代码库探索、测试和分类等任务使用子智能体
- ❌ 不要让子智能体处理需要主线程完整上下文的任务
- ❌ 不要为简单线性任务使用子智能体（增加不必要的开销）
