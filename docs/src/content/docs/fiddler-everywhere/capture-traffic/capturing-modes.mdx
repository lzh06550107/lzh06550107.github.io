Fiddler Everywhere 是一个 Web 调试代理，可用于捕获 HTTP(S)、WebSocket、Server-Sent Events（SSE）和 gRPC 等流量。作为本地转发 TLS 代理，它既可以拦截本机应用流量，也可以捕获局域网内远程设备的流量。

## 可用捕获模式

Fiddler Everywhere 提供多种捕获模式，用于适配不同调试场景：

- **System Capturing**：通过修改操作系统代理设置，捕获系统范围内的流量。
- **Network Capturing**：在网络适配器层级捕获流量，不依赖代理配置。
- **Independent Browser Capturing**：使用沙盒化浏览器实例进行隔离流量捕获。
- **Terminal Capturing**：从专用终端会话中捕获命令行程序流量。
- **Explicit Capturing**：捕获手动配置为使用 Fiddler 代理的应用流量。
- **Remote Traffic Capturing**：捕获本地网络中其他设备的流量。

## 如何选择捕获模式

不同模式适合不同场景：

| 场景 | 推荐模式 |
| --- | --- |
| 调试本机上大多数应用的通用流量 | System Capturing |
| 代理设置导致问题，或需要更低层级分析 | Network Capturing |
| 只测试 Web 应用，不影响系统其他流量 | Independent Browser Capturing |
| 调试 CLI 工具、Node.js 应用或命令行程序 | Terminal Capturing |
| 测试移动应用、IoT 设备或分布式系统 | Explicit Capturing 或 Remote Traffic Capturing |
| 捕获发送到某个服务端的流量 | Reverse Proxy |

## System Capturing

System Capturing 是最全面的捕获模式。它通过修改操作系统代理设置，将本机到互联网之间的 HTTP、HTTPS、WebSocket、SSE 和 gRPC 流量路由到 Fiddler。

适用场景包括：

- 通用应用调试。
- 系统范围流量分析。
- 桌面应用测试。
- 同时捕获多个应用的流量。

(图略)

基本步骤：

1. 启动 Fiddler Everywhere。
2. 启用系统捕获。

## Reverse Proxy

Fiddler Everywhere 支持反向代理模式。可以通过内置 Reverse Proxy 功能，或通过自定义反向代理规则，捕获发送到某个服务端的流量。

(图略)

## Network Capturing

Network Capturing 是 beta 功能，工作层级比传统 HTTP 代理更低，会直接从网络适配器捕获 TCP 流量。该模式适用于 Windows 和 macOS。

主要优势：

- 不需要代理配置。
- 可以捕获不支持代理的应用流量。
- 可以更细粒度地控制被监控的进程和 IP 范围。
- 可以绕过某些代理限制，例如 macOS 上 Safari WebSocket 流量不遵循代理设置的问题。

适用场景包括：

- 应用忽略系统代理设置。
- 在 macOS 上调试 Safari WebSocket。
- 更低层级的网络分析。
- 代理配置被企业策略限制。

(图略)

## Independent Browser Capturing

Independent Browser Capturing 提供独立、沙盒化的浏览器环境，用于隔离分析浏览器流量。目前主要支持 macOS 上基于 Chromium 的浏览器。

主要优势：

- 不需要修改系统代理。
- 测试环境隔离。
- 不需要单独安装证书。
- 适合 Web 应用测试。

适用场景包括：

- Web 应用调试。
- 不影响系统其他流量的测试。
- 证书安装受限的环境。
- 快速浏览器测试会话。

(图略)

## Terminal Capturing

Terminal Capturing 会提供一个已预配置 Fiddler 代理的专用终端会话，适合调试命令行工具和服务端应用。

主要优势：

- 独立终端环境。
- 不需要修改系统配置。
- 适合 CLI 工具和 Node.js 应用。
- 代理设置已预配置。

适用场景包括：

- Node.js 应用调试。
- CLI 工具和命令行工具测试。
- `curl` 命令分析。
- API 测试脚本。

(图略)

## Explicit Capturing

Explicit Capturing 适用于那些手动配置为使用 Fiddler 代理地址的应用。默认代理地址通常是 `127.0.0.1:8866`。即使系统捕获关闭，只要目标应用显式使用该代理，也可以被 Fiddler 捕获。

配置要点：

- 代理地址：`127.0.0.1:8866`。
- 需要在目标应用中手动配置代理。
- 适用于支持 HTTP 代理设置的应用。

示例：

```bash
# curl command using Fiddler's proxy
curl --url https://www.example.com/ -x 127.0.0.1:8866 --ssl-no-revoke -v
```

适用场景包括：

- 指定应用测试。
- 远程设备配置。
- 有自定义代理设置的应用。
- 需要精确控制的测试场景。

## Remote Traffic Capturing

Remote Traffic Capturing 用于分析本地网络中其他设备的流量，包括手机、平板、IoT 设备、其他电脑和游戏主机等。

基本要求：

1. 将远程设备配置为使用 Fiddler 代理，例如 `[Fiddler-IP]:8866`。
2. 在远程设备上安装 Fiddler CA 证书。
3. 确保远程设备和运行 Fiddler 的主机位于同一网络。

支持设备包括：

- Android 手机和平板。
- iPhone 和 iPad。
- 游戏主机。
- IoT 设备。
- 其他电脑和笔记本。

:::tip[只捕获远程流量]
如果只捕获远程设备流量，通常不需要在 Fiddler 主机上安装 Fiddler CA，只需要在要监控的远程设备上安装证书。
:::

## 协议支持

Fiddler Everywhere 在不同捕获模式下支持多种协议。

### HTTP 版本支持

Fiddler Everywhere 支持捕获和编写 HTTP/1.x 与 HTTP/2 流量。应用中提供专门的列显示 HTTP 版本，包括客户端到 Fiddler 的协议版本，以及 Fiddler 到远程端点的协议版本。

- **客户端 HTTP 版本**：客户端与 Fiddler 之间的协议版本
- **远程 HTTP 版本**：Fiddler 与远程终点之间的协议版本

HTTP/2 要点：

- HTTP/2 默认启用，也可以在 Settings > Connections 中关闭。
- 当客户端和服务端都支持时，连接默认使用 HTTP/2。
- 关闭 HTTP/2 后，Fiddler 会强制使用 HTTP/1.1 通信。
- Fiddler 会根据需要转换 HTTP 版本（例如，将 HTTP/2 客户端转换为 HTTP/1.1 服务器）

注意事项：

- 部分浏览器会在多个标签页之间共享 HTTP/2 连接，并在标签页关闭后保持连接。
- 如果遇到异常，可以尝试重启浏览器。
- HTTP/2 伪标头会按原始传输顺序显示。

### Streaming HTTP

Streaming HTTP 使用标准 HTTP 协议和分块传输编码，在单个长连接上分块发送数据。通信方向通常是单向的，由服务端发送分块数据，客户端接收后如需回应则使用新的连接。

Fiddler 对 Streaming HTTP 的支持包括：

- 兼容所有捕获模式。
- 复用标准 HTTP inspectors。
- 自动解码已编码消息。

### WebSocket

WebSocket 基于 TCP 连接提供全双工通信。它不同于 HTTP，但设计上可运行在 HTTP 端口上，并支持 HTTP 代理。

Fiddler 对 WebSocket 的支持包括：

- 兼容所有捕获模式。
- 提供专用 WebSocket inspectors。
- 自动解码已编码消息。
- 可检查握手、元数据和消息。

### Server-Sent Events

Server-Sent Events（SSE）允许服务端通过 HTTP 向客户端推送数据，适合实时更新场景，不需要客户端轮询。

Fiddler 对 SSE 的支持包括：

- 可用于 HTTP/1.1 和 HTTP/2。
- 所有捕获模式可用。
- 提供专用 SSE inspectors，用于分析握手和消息。

### gRPC

gRPC 是 Google 开源的 RPC 框架，基于 HTTP/2 构建，常用于微服务以及移动端到后端的通信。

Fiddler 对 gRPC 的支持包括：

- 兼容所有捕获模式。
- 提供专用 gRPC inspectors。
- 支持检查握手和消息。

:::caution[gRPC 前提]
gRPC 需要在 Settings > Connections > Enable HTTP/2 support 中启用 HTTP/2 支持。
:::

### Socket.IO

Socket.IO 提供双向、低延迟、基于事件的客户端与服务端通信，常用于实时应用。

Fiddler 对 Socket.IO 的支持包括：

- 适用于所有捕获模式。
- 提供专用 Socket.IO inspectors。
